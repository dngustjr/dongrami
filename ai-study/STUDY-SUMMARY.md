# 레슨 요약집 (공구 업무 자동화 관점)

레슨이 끝날 때마다 한 건씩 추가됩니다. 찾아볼 때는 레슨 번호나 키워드로 검색하세요.

## 14/01 에이전트 루프
- **한 줄**: 에이전트는 "생각 → 도구 사용 → 결과 확인"을 끝날 때까지 되풀이하는 반복(ReAct)이고, 대화창(챗봇)과 다른 점은 이 반복에 도구와 종료 규칙이 있다는 것이다.
- **필수 5요소**: 대화 기록 / 도구 목록 / 종료 조건 / 최대 횟수 제한 / 도구 결과를 읽기 좋게 바꾸는 장치.
- **공구 적용**: "주문 조회 → 재고 확인 → 답변"을 스스로 이어서 수행. 어떤 프레임워크를 써도 속은 이 반복.
- **주의**: 최대 횟수가 없으면 무한 반복, 도구가 가져온 외부 글(PDF 등)은 믿으면 안 되는 입력(그 안의 "삭제해"라는 문장을 따르면 안 됨).

## 14/02 ReWOO와 계획 후 실행
- **한 줄**: 계획자가 먼저 전체 계획을 짜고, 일꾼이 실행하고, 해결자가 결과를 모아 답한다. ReAct보다 토큰이 약 5분의 1.
- **공구 적용**: 순서가 정해진 업무(발주 취합 등)는 ReWOO, 고객 응대처럼 상황이 바뀌는 건 ReAct.
- **주의**: 단순한 일(도구 한 번+요약)에는 과한 설계. 일꾼 오류는 해결자가 문자열로 보고 대응.

## 14/03 Reflexion (실패에서 배우기)
- **한 줄**: 실행하고(행동자), 점수를 매기고(평가자), 실패 이유를 말로 적어(반성자) 다음 시도 때 보여 준다.
- **공구 적용**: 응대 실패 사례를 반성문으로 저장해 다음 응대에 반영. Claude Code의 CLAUDE.md도 같은 원리.
- **주의**: 낡거나 틀린 반성문이 쌓이면 이후 시도를 오히려 망친다(memory rot) → 유효기간, 중복 제거, 압축.

## 14/04 Tree of Thoughts와 LATS
- **한 줄**: 한 길만 가지 않고 여러 갈래를 펼쳐 점수 높은 길을 파고든다(ToT), 거기에 실행 결과와 반성까지 합친 것이 LATS.
- **공구 적용**: 복잡한 판단에서 여러 안을 비교할 때.
- **주의**: 비용이 100~1000배. 채점 신호가 약하면 엉뚱한 길로 가므로, 코드 테스트처럼 싸고 믿을 만한 채점이 있을 때만.

## 14/05 Self-Refine과 CRITIC
- **한 줄**: Self-Refine은 AI가 스스로 검토해 고치는 방식, CRITIC은 검색·계산기·테스트 같은 외부 도구로 검증한 결과로 고치는 방식.
- **공구 적용**: 공지문의 가격·마감일은 계산기·원본 엑셀로 대조.
- **주의**: "괜찮다"는 AI의 말만으로 멈추면 틀린 것도 통과. 외부 검증 통과를 기본 종료 조건으로.

## 14/06 도구 사용과 함수 호출
- **한 줄**: AI가 도구를 쓸 때 이름·설명·입력 형식(스키마)이 정해져 있어야 하고, 호출 값은 전부 검증해야 한다.
- **공구 적용**: 결제·발주처럼 돈이 나가는 도구는 형식이 틀리면 엄격히 거부. 없는 도구는 지어내지 말고 "못 한다"고 말하게.
- **주의**: 도구 설명이 겹치면 엉뚱한 도구를 고름(가장 흔한 실패 원인). 여러 번 이어지는 긴 작업에서 맥락이 흐려짐.

## 14/07 메모리 가상 컨텍스트 (MemGPT)
- **한 줄**: AI의 작업대(프롬프트)는 작으니, 컴퓨터가 RAM과 디스크를 나누듯 "항상 보이는 기억(core)"과 "필요할 때 검색하는 창고(archival)"로 나눈다.
- **공구 적용**: 고객 알레르기·주소 같은 핵심은 core, 지난 주문 이력은 archival.
- **주의**: 중요한 정보를 창고에만 두면 AI가 검색을 안 해서 놓침. 기억 오염(틀린 정보 저장)도 주의.

## 14/08 메모리 블록과 수면 에이전트
- **한 줄**: 에이전트의 기억을 역할별 블록(사용자 정보/성격/작업/안전)으로 나누고, 일하지 않는 시간에 "수면 에이전트"가 기억을 정리한다.
- **공구 적용**: 고객 정보·주의사항 블록을 항상 보이게 두고, 밤에 대화 기록을 정리해 요약.
- **주의**: 블록이 꽉 차 요약되면 오래된 중요 정보가 사라질 수 있음.

## 14/09 하이브리드 메모리 (Mem0)
- **한 줄**: 기억을 벡터(비슷한 것 찾기)·KV(정확한 값)·그래프(관계)에 나눠 저장하고, 관련도+중요도+최신성으로 점수를 매겨 꺼낸다.
- **공구 적용**: 배송시간은 KV, "같은 건물 고객"은 그래프. 문의 응대는 최신성을 가장 높게.
- **주의**: 정보가 바뀌면 세 저장소 모두에서 옛 기록을 무효화해야 함.

## 14/10 스킬 라이브러리 (Voyager)
- **한 줄**: 성공한 방법을 실행 코드 스킬로 저장해 두고 검색·조합해 쓴다(자동 커리큘럼+스킬 라이브러리+반복 프롬프팅).
- **공구 적용**: "주문 엑셀 읽기" 같은 스킬을 쌓아 재사용.
- **주의**: 부모 스킬이 자식 최신 버전을 몰래 쓰면 오작동(→버전 고정), 비슷한 스킬이 늘면 태그로 구분.

## 14/11 HTN 계획과 진화 검색
- **한 줄**: HTN은 큰 일을 "시작 조건"이 붙은 단계로 쪼개 순서가 틀릴 수 없게 하고(AI 제안은 조건 검사 통과분만 채택), 진화 검색은 AI 변형+기계 채점으로 점점 개선한다.
- **공구 적용**: 환불은 승인 후에만 입금(HTN), 택배비 절감은 실제 청구액으로 채점(진화 검색).
- **주의**: AI가 매기는 점수는 기준이 흔들려 채점기로 부적합.

## 14/12 Anthropic의 워크플로 패턴
- **한 줄**: 순서를 적을 수 있으면 워크플로로 시작하고, 모를 때만 에이전트를 쓴다. 패턴 다섯: 체인, 라우팅, 병렬, 오케스트레이터-워커, 평가자-개선자.
- **공구 적용**: 발주·정산=체인, 문의 분류=라우팅, 환불 판단 다수결=병렬, 공지문 검수 반복=평가자-개선자, 새 공급처 발굴=에이전트.
- **주의**: 새 업무는 에이전트로 탐색한 뒤 절차가 굳으면 워크플로로 고정.
